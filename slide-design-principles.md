# Slide design principles (template)

Visual and structural rules for building slides. This complements the communication
guidelines (which govern prose/voice); this file governs how a slide looks and
carries one idea.

**To make it yours:** copy this file to `slide-design-principles.local.md` and edit.
The skill reads the `.local` version first and falls back to this template. The
`.local` file is git-ignored, so your personal distillation stays private. Keep this
template to general, widely-known design principles only, so it is safe to publish.

Apply these when choosing an archetype, laying out a slide, and deciding what to cut.

## One slide, one idea

- Each slide makes a single point. If a slide needs two takeaways, split it.
- The action title states that point. The body only proves it.
- If you cannot say the point out loud in one breath, the slide is overloaded.

## Reduce before you design

- Cut every element that does not support the one point. Less on the slide, more in
  the viewer's head.
- Prefer 3 to 5 items over 7+. Group and label instead of listing everything.
- Replace sentences with phrases. The speaker adds the words; the slide holds the anchors.
- No slide is a document. If it reads like a report, move detail to an appendix or notes.

## Hierarchy guides the eye

- Make the most important element the most prominent: size, weight, position, colour.
- One clear entry point per slide. The eye should know where to land first.
- Top-left to bottom-right reading order in a left-to-right language. Place the
  conclusion where the eye ends, or at the top as a banner.
- Align everything to a grid. Consistent alignment reads as calm and deliberate.

## Contrast and emphasis

- Use contrast to signal what matters: a single highlighted number, row, or box.
- Emphasis only works if it is rare. If everything is bold, nothing is.
- Keep enough contrast between text and background for easy reading (and for a room
  with a projector and daylight).

## Whitespace is a tool

- Empty space is not wasted space. It frames the point and lowers cognitive load.
- Give the key element room to breathe. Crowded slides feel anxious and unclear.
- Consistent margins and gutters across slides; do not fill to the edges.

## Colour with discipline

- Colour carries meaning, so use it sparingly and consistently. One accent, used
  only for emphasis, beats a rainbow.
- Keep a consistent palette across the deck (house style owns the exact values).
- Never rely on colour alone to convey meaning; pair it with label, position or shape.

## Data and charts

- Pick the chart that answers the question: trend over time (line), comparison
  (bar), composition (stacked/share), relationship (scatter).
- Maximise data-ink: strip gridlines, borders, 3D, shadows and redundant legends.
- Label directly on the data where you can, instead of a separate legend.
- State the takeaway in the title ("Promo spend grew 18% in Q3"), not a neutral
  label ("Promo spend"). The chart proves it; the title says it.
- One chart per slide unless you are explicitly comparing two.

## Type and legibility

- Few type sizes, used consistently: title, body, caption. Hierarchy, not variety.
- Big enough to read from the back of the room. When unsure, larger.
- Left-aligned body text is easiest to scan. Avoid centred paragraphs and all-caps runs.

## Consistency across the deck

- Repeat layout patterns so the audience learns where to look. Same element, same place.
- Section dividers to signpost structure. The audience should always know where they are.
- A deck that looks like one system reads as more credible than clever one-off slides.

## Flow and signposting

- Order slides so each one sets up the next. Horizontal logic: read only the titles
  and the story should hold.
- Use an agenda and section dividers for decks over ~8 slides.
- End on the ask, not a summary of everything said.
